# 週次35投稿 Runbook（2026-08-24 Coco承認）

**この文書はルール本体を持たない。** ルールの正典は `CLAUDE.md` の一箇所だけ。
旧ver.7.1／7.2の指示文はルールを二重に持っていたため、CLAUDE.mdと20箇所以上で食い違っていた
（例：「設計→仕組みに置換（絶対）」だが現行では「仕組み」自体が禁止語／
Xの1行目・💍の扱い・funnel本数・削除タイミング・画像の組合せ数などがすべて逆）。
ルールが増えたら **CLAUDE.md だけ** を直す。この Runbook は手順書のまま置いておく。

---

## ① 週次生成（毎週金曜7:00の自動実行用）

```
週次35投稿を生成してください。対象週：YYYY-MM-DD〜YYYY-MM-DD（火曜〜翌月曜）

【最重要】ルールの正典は CLAUDE.md です。この指示文にルールを書きません。
必ず CLAUDE.md を読み、そこに書かれた恒久ルールに従って生成してください。
この指示文と CLAUDE.md が食い違ったら、CLAUDE.md を優先し、食い違った箇所を報告してください。

■ 担当範囲（厳守）
・担当ファイルは posts/week_YYYY_MM_DD_YYYY_MM_DD.json のみ（アンダースコア区切り）
・X診断／Threads診断／LINEスタンプ／スタンプ宣伝／note は1バイトも変えない
・posts/index.json は自分の週を追加するだけ（他項目の行に触らない）
・「全入れ替え」「全削除して作り直し」は禁止

■ 生成前に必ず読むファイル
1. CLAUDE.md（恒久ルールの正典）
2. reference/coco_methodology.json（七つの原理＋三つの前提）
3. reference/coco_voice_source.json（Coco素材集・二層ルール）
4. reference/post_guidelines.json
5. reference/weekly_metrics.json（直近2週の実測。勝った型に配分を寄せる）
6. reference/episodes_soshiki.json ＋ reference/episode_usage_log.json
7. reference/image_prompt_rules.json（画像プロンプトの正典）

■ 本数と枠
・X：1日2本（06:00 / 22:00）×7日＝14本
・Threads：1日3本（07:00 / 10:00 / 19:00）×7日＝21本
・合計35本。1日ずつ生成してJSONに逐次保存（途中停止時は未完了日から再開）

■ エピソード割り当て
・episode_usage_log.json を読み、各投稿日の30日前より後に使ったエピソードは除外する
　（基準日は「その投稿の日付 − 30日」。週の初日で一律に計算しない）
・1投稿1エピソードの1対1。使い回し禁止
・組織寄り→X／関係寄り→Threads。どちらにも通じる素材は角度を決めてから割り当てる
・生成後、使用したエピソードIDと投稿日を episode_usage_log.json に追記し、
　episodes_soshiki.json の used_in も更新する

■ 完成後チェック（省略禁止・2段構え）
1. 機械チェック：python3 tools/full_check.py posts/week_YYYY_MM_DD_YYYY_MM_DD.json
   → 要修正0件になるまで直す（Xの曜日固定テーマのfunnel土日配置のみ例外可）
2. 判断チェック：ツール末尾の出力を使って必ず目視で埋める
   ①35本の処方を一行ずつ書き出して並べ、言い換えただけの重複が3本以上ないか
   ②35本すべてに原理01〜07を割り当て、1プラットフォームで5本以上に偏っていないか
   ③比喩一本化／再発パターン3型／8割読み切り／ブランド整合性
報告時は、機械で確認した項目と目視で確認した項目を分けて書くこと。
目視していない項目を「クリア」と書かない。

■ push
git pull --rebase origin main → 自分のファイルのみ add/commit →
フィーチャーブランチに push → main にも push（Pages反映）。
push失敗は最大3回・5秒間隔でリトライ。3回失敗ならローカル保存して終了（生成データは消さない）。
完了後、公開URL（https://coco930118.github.io/weekly/）を添えて報告。
```

## ② グローアップ（既存週の磨き込み用）

```
既存週の35投稿をグローアップしてください。対象週：posts/week_YYYY_MM_DD_YYYY_MM_DD.json

【最重要】ルールの正典は CLAUDE.md です。この指示文にルールを書きません。
必ず CLAUDE.md を読み、そこに書かれた恒久ルールに従ってください。
この指示文と CLAUDE.md が食い違ったら、CLAUDE.md を優先し、食い違った箇所を報告してください。

■ 担当範囲（厳守）
・触るのは対象週の posts/week_*.json のみ
・X診断／Threads診断／LINEスタンプ／スタンプ宣伝／note は1バイトも変えない
・すでに配信済みの投稿は、配信実態と食い違うため原則として本文を変えない
　（変える場合は「配信済みだが記録として直す」と明示する）

■ 手順
1. CLAUDE.md と reference/weekly_metrics.json（直近実測）を読む
2. 機械チェックを回す：python3 tools/full_check.py posts/week_*.json
3. 判断チェックをツール末尾の出力で必ず目視で埋める
   ①35本の処方を一行ずつ書き出して並べ、言い換えただけの重複が3本以上ないか
   ②35本すべてに原理01〜07を割り当て、1プラットフォームで5本以上に偏っていないか
   ③比喩一本化／再発パターン3型／8割読み切り／ブランド整合性
4. 結果を「対象ID → 判定（OK／要修正）→ 要修正の具体箇所と修正案」の順で出す
5. 【重要】修正は提案のみ。Cocoの承認を得てから確定する（勝手に直さない）
6. 承認後に修正し、機械チェックを再実行して要修正0件を確認してから push

■ 実測がある場合の優先事項
weekly_metrics.json の直近2週で勝った型に寄せる。
配分の目安を上書きしてよい根拠は、このログの実測のみ。

■ 報告の作法
・機械チェックで確認した項目と、目視で確認した項目を分けて書く
・恒久ルールと個別指定がぶつかったら、恒久ルールを採用したうえで、どこがぶつかったかを明示する
```

## 旧指示文（ver.7.1／7.2）を使わない理由の記録

CLAUDE.md と衝突していた主な箇所（2026-08-24時点）：

| 旧指示文 | 現行の恒久ルール |
|---|---|
| 「設計」→「仕組み／仕組み化」に置換（絶対） | 「仕組み」も禁止語（抽象語スキャンの検出語） |
| Xの1行目＝痛みの名指し／逆説／数字／あなたへの一撃 | 例外なく読者の声を「」で引用して始める |
| Xは「あなた」を主語に。「私が〜」の独白禁止 | 相談を受けた流れ（引用→受け口→判定先出し）。わたし目線の観察締めも週3〜4本可 |
| 💍は署名回のみ・🫶と重ねない | Threads全21本の最終行が💍タグライン（4パターン分散）。ひとことは🫶 |
| Threadsの締めは「あなたは〜？」の投げかけ | 拡散帯17本は問いかけで締めない（余韻） |
| note導線＝クラスタ週3・目安8〜10本 | funnel週8本固定（X4＋Threads4）・本文は軽い一行＋返信2に定番プロミス |
| 前々週分を削除し最新2回分維持 | 配信終了から30日（4週間）保持 |
| X 140字以内／140〜220字 | 字数指定は撤廃（圧縮ルール＝5〜7行） |
| エピソードは一般論に変えて登場人物も変更 | 二層ルール（相談者は創れる／わたしは創らない） |
| 画像＝7組合せ×5アングル | 14組合せ／実運用は動物7周期×5本・アングル5周期×7本 |
| JSON＝content/quote/note_funnelのみ | episode_id・image_prompt・self_replies が必須 |
| ひとこと15字以内目安 | 23字以内・理想15〜20字 |

※旧指示文は文書内でも自己矛盾していた（8.5節＝14通り／末尾の追記＝7通り、
ファイル名がハイフンとアンダースコアで混在）。
