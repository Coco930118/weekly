## 三段階でひとつ（2026-08-25 Coco決定）

**7:00 生成 → 12:00 グローアップ → Cocoの指示でWチェック。** 三つが別の仕事をする。

| | 7:00 生成 | 12:00 グローアップ | Wチェック |
|---|---|---|---|
| **作り方** | **1日ずつ**作る | **7日分を読者の順で一続きに読む** | Cocoが読む＋Codeが回す |
| **持っている情報** | なぜそう書いたかの理由 | **JSONだけ**（理由を知らない） | 両方＋Cocoの目 |
| **やること** | 作る＋機械チェックを0件まで | **目視5つを通しで** | 全媒体・全ルール |
| **本文** | 書く | 要修正は提案のみ | 提案のみ |

**なぜ12:00に固有の仕事があるか。**
7:00は「1日ずつ生成してJSONに逐次保存」で作る。だから**7日分を通しで読んだセッションが一つも存在しない**。
そして目視5つのうち3つ（処方の言い換え重複・原理の配分・既視感）は、**通しでしか見えない**。
火の「自分の予定を先に入れる」と日の「日曜朝に自分の席を取る」が同じ処方だと気づくには、7日分を並べる必要がある。

もう一つ。**7:00は「作った本人」**で、なぜそう書いたかの理由をコンテキストに全部持っている。
だから「これは意図的に似せた」と自分で説明がついてしまう。
**12:00はその理由を持たない。JSONだけを見る。読者と同じ条件で読む。**
編集部が一晩寝かせるのと同じ効果で、寝かせる価値は時間の長さではなく
**作った文脈を持っていないこと**にあるので、5時間でも成立する。

**7:00の負担も減る。** 35本書き切った直後に目視5つまでやらせるのは無理だった。
**7:00は機械チェックまで。目視は12:00に渡す。**

## ⑧ Cocoが指示｜Wチェック（三段階目）

**Cocoが読むのと同時に、Codeが全媒体を回す。** スケジュール実行ではなく、Cocoが投げる。

- **いつ**：**土曜、noteの生成が終わったあと**（その週の生成が全部出揃い、前週の実測も出ている）
- **どこで**：**Wチェック専用のセッションを立てる**。生成にも通し読みにも参加していないので、いちばん白紙で読める。
  Cocoが立ち会うので、スケジュール実行との衝突も起きない。
  **このセッションだけは持ち場を持たず、全媒体を横断してよい**（Cocoの承認を得てから直す）
- **スコープ**：「全て恒久ルール通りかチェックして」＝**その週の全媒体**（35投稿＋診断14本＋note9本）。
  リポジトリ全体をさらいたいときは「過去記事も全部見て」と足す

```
全て恒久ルール通りかチェックして。対象週：YYYY-MM-DD〜YYYY-MM-DD

【最重要】ルールの正典は CLAUDE.md と rules/ です。この指示文にルールを書きません。
このセッションはWチェック専用です。持ち場を持たず、全媒体を横断して見てよい。
```

### 実測の反映（Cocoが数字を出したとき）

**数字は、チャットに一言か、スクショで出せばいい。** 記入・保存・pushはCodeがやる。
書式は `reference/weekly_metrics.json` の `how_to` にある。最小はこれだけ：

```
今週 平均50・最高243の実験型・フォロワー+12・note300ビュー・入会0
診断は 本文43 / コメント8（8/23時点）
```

**診断は必ず2値で**（本文の表示／コメントの表示／いつ時点か）。
本文表示は配信からの経過日数にほぼ比例するので、経過日数が揃っていない日同士を強弱で比べない。

**反映できる範囲は3つに分かれる。ここを混ぜない。**

| 対象 | できること |
|---|---|
| **配信が終わった週** | **数字を記録するだけ。本文は直さない**（配信実態と食い違うため） |
| **生成済み・未配信の週** | **配分・型・用量を直せる。** ここが実測の効く先。本文の全面書き直しはしない |
| **次の生成** | `weekly_metrics.json` に入れておけば、7:00の生成が読んで配分を寄せる |

**手順**
1. 数字を `reference/weekly_metrics.json` の `weeks` に追記する（週・5指標・診断の2値・取得時点）
2. 型ごとに並べて、勝った型・負けた型を出す
3. **未配信の週があれば、その配分に反映する**（型配分の目安を実測で組み替える）
4. `reference/todo.md` に判定期限の来た試験があれば、その基準で判定してCocoに提案する
5. 3行の申し送りで締める
   　増やす：〈型〉が中央値の〇倍。翌週は〇本→〇本
   　減らす：〈型〉が2週連続で下回った。〇本に落とす
   　試す：〈試験名〉の判定が〇/〇。継続／用量変更／中止のどれかを提案

**配分・型・用量を上書きしてよい根拠は、このログの実測だけ。** 感覚で変えない。
記入がない週はスキップしてよい（欠測で作業を止めない）。

**Cocoは同じ週を自分の目で読む。** Codeが機械と通し読みで拾えないもの——
実際の読者の温度・そのときの気分・言葉の手触り——はCocoの側にしかない。
**二人が別のものを見るから、Wチェックになる。** 同じチェックリストを二回回すのはWチェックではない。
