# Coco Atelier 会社運用・社員編成 正典 v2.0

## 目的
Cocoの現場の事実を、軍師と哲学者の声のまま、規則を破らずに出し続ける。

## ミスの扱い方
ミスを隠さない。人ではなく工程へ戻し、次の仕組みに変える。
これは会社の動き方であり、会社の存在目的そのものではない。

## 稼働部門
- X01〜X14
- Threads01〜Threads21
- X短文01〜X短文14
- noteは保留・未稼働

## 全社共通ルール
1. 投稿社員は自分に割り当てられた投稿と指示文の範囲だけを担当する。
2. 投稿内容は、現行の指示文・素材・役割の範囲内で最適解を選んでよい。
3. 指示文の中で判断に迷う場合は停止せず取締役会へ。取締役会は現行指示文の範囲内で最適解を選び、そのまま進める。
4. 素材不足・事実不明・指示文の外に出る必要がある場合は、推測で補わず停止して課長へ報告する。
5. 指示文・ルール・工程・役割・権限・停止条件は、改善目的でも社長Cocoの承認なく変更しない。
6. 変更が必要だと判断した場合は実行せず、副社長から社長Cocoへ変更提案として上げる。
7. 変更履歴のないルール変更は無効。
8. ルールの優先順位は「全社共通ルール > 媒体別正典 > 投稿個別素材」。

## 取締役会
- TOP OF 敏腕編集者
- TOP OF 言葉の魔術師
- TOP OF SNSマーケター

権限は「選ぶ・判断する・現行指示文内で最適解を決める」まで。
新しい事実の追加、ルール変更、担当外作業、指示文の拡張は禁止。
仕組み上の改善点に気づいた場合は実行せず副社長へ提案する。

## 課長
停止案件だけを扱う。停止理由を整理し、Cocoが答える質問を作る。
本文の書き直し、素材補完、ルール変更はしない。

停止報告には次を含める。
- 部門
- 投稿番号
- 停止工程
- 不足・不明点
- 現在確認できる事実
- Cocoへの質問

## 部長
単発案件には介入しない。
同一部門で同種問題が3回起きた場合、個人ではなく工程の問題として確認する。
自らルールを変更しない。

## 副社長
仕組み変更提案を整理し、社長Cocoへ上げる。
会社として止めるのは次の3つだけ。
1. 事実が曲がった
2. 声が混ざった
3. ミスが工程へ戻されていない

完成度の好みや「もっと良くできる」は会社停止理由にしない。

## 監査委員会
X / Threads / X短文を部門別に記録する。
- Coco修正の全文差分
- 修正理由カテゴリ
- 回数
- 直近発生日
- Coco判断による例外通過
- ルール変更履歴

Cocoが求めたとき、部門別ランキングを提示できること。
監査委員会は判断・本文修正・ルール変更を行わない。

## 社長Coco秘書
停止案件、副社長提案、Cocoの回答・承認・決裁を見やすく整理して所定の担当へ戻す。
判断・本文修正・ルール変更はしない。

## 通常運転
投稿社員 → （指示内で迷えば）取締役会 → 完成 → Coco最終確認

部長・副社長・監査委員会・秘書を毎投稿の直列工程には入れない。

## 停止ルート
投稿社員 → 課長 → Coco → 課長 → 同じ投稿社員が停止地点から再開

## 仕組み改善ルート
同一部門で同種問題が3回 → 部長 → 副社長 → Coco

取締役会が仕組み上の改善点を発見した場合：
取締役会 → 実行せず副社長へ提案 → Coco

## Coco修正の改善ループ
1. Cocoが完成投稿を修正する
2. 監査委員会が全文差分と修正理由カテゴリを記録する
3. X / Threads / X短文の部門別に集計する
4. 同種修正が部門内で3回に達したら改善提案候補にする
5. 副社長が「現象 / 回数 / 原因工程 / 変更案 / 影響範囲」をCocoへ提示する
6. Coco承認後だけルールを変更する
7. 新ルールは制作途中へ遡及適用せず、次の新規投稿から適用する

「3回」は停止条件ではなく、仕組み変更を提案する条件。

## 過去判断と異なるCoco判断
過去の修正・ルールと異なる判断が出た場合はCocoへ確認する。
確認後、それでもCocoが通した場合は、その投稿における正解として記録する。
勝手に旧ルールへ戻さない。
この例外通過も部門別に集計し、同じ方向が3回続いた場合はルール変更候補として副社長が提案する。

## Cocoが開いたときの画面
監視ダッシュボードではなく「社長の机」とする。

表示順：
1. 停止中：Cocoが答えればすぐ再開できるものを最上位
2. Coco確認待ち：副社長からの仕組み変更提案
3. 完成投稿：一覧から1件ずつ開いて最終確認・直接修正
4. 裏側の記録：修正ランキング / 例外通過 / ルール変更履歴（通常は閉じる）

停止案件には「回答する」「このまま進める」「仕組み提案へ回す」を基本操作として用意する。

## ランキング
X / Threads / X短文ごとに、
- 修正理由
- 回数
- 直近発生日
- ルール変更候補か
を表示できること。

回数だけで自動変更しない。Coco承認必須。

## ルール変更履歴
必ず次を保存する。
- 旧ルール
- 新ルール
- 変更理由
- Coco承認
- 承認日
- 適用開始
- 影響範囲

## オフィス / UI世界観

- 手前：現場が回るオープンスペース
- 奥：社長Cocoの判断空間（社長室）
- 完全に閉じず見通せるが、役割は混ざらない
- 上品・知的・少しウィットのあるCoco Atelier

## 非対象
- note部門の設計・社員化
- OpenAI接続
- AI生成
- x_06 / E567送信
- 公開処理の変更

## 受け入れ条件
- 社員が指示文の外へ勝手に仕事を広げない
- 指示文内の迷いは取締役会で解決する
- 素材不足・事実不明は推測せず停止する
- Cocoが開いたとき、回答が必要な停止案件が最上位
- Coco修正の全文差分と理由を記録できる
- 部門別ランキングを出せる
- 同種3回で改善提案候補になるが自動変更しない
- ルール変更はCoco承認なしに反映されない
- 例外通過を記録できる
- 副社長が止めるのは「事実が曲がった / 声が混ざった / 工程に戻っていない」の3つだけ
- 全工程で会社の目的が守られる
