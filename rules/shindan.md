## 診断 共通ルール（X診断・Threads診断 共通・毎回必ず適用）

対象：X診断・Threads診断のすべての回。生成／グローアップ時に、各回のフックと選択肢に必ずこの2ルールを適用する（既存ルールに上乗せ・衝突時は本ルールを優先）。

### ルール1：冒頭フックの「その瞬間」法（爆発力を上げる）
設問（「いちばん近いのはどれ？」等）の前に、感情を刺激する“その瞬間”を再現する一文を必ず先頭に置く。読者を説明でなく「場面」に放り込んでから設問へ渡す。
- 型：「〈相手の一言 or 突きつけられた状況〉」と〈言われた／なった〉瞬間、どう〈返す／動く〉？（**設問に主語を置かない**。下記「文体」参照）
- 一般論・説明（「〜な人へ」「〜についての診断です」）で始めない
- 読者が実際に食らう“セリフ・場面”を先頭に置き、痛点をその場で再生させる
- 強い一文 → 設問 → 選択肢の順。強い一文は投稿フレーム（フック＋設問＋CTAのコピー単位）の先頭に入れる
- 例：「『その経験は、うちの業界では通用しない』と言われた瞬間、どう返す？」
- NG例：「どのタイプ？」「〜に関する診断です」（弱い・説明的）

### ルール2：選択肢のバランス＆導線設計（答えの位置を毎回変える）
- 【最重要・答えを固定しない】どれが“効く／理想”の選択肢かは、回ごとに変える。毎回同じ位置（例：いつもC・いつもD）を正解にしない
- 【正解を1つに絞らない回も混ぜる】全部に一理ある／状況次第で答えが変わる回もあってよい。診断の面白さは「わたしはこれだ」という発見であって、“正解当て”ではない
- 全選択肢を誠実に肯定で拾う。「受け入れ・引く・無言・無視」に見える選択肢も、消極でなく“別の強さ”として描く（逃げに見せない）
- 重心（理想）を置く回でも“これが正解”と言い切らず、読者が自然にそこへ向かう温度で。ただし理想の位置（A/B/C/D）は毎回動かす
- 【回またぎのバランス】週7本／複数回で、理想の位置を散らす：連続で同じ位置が正解にならないようにする
- **【語尾を4つそろえない】（2026-08-31 Coco決定・恒久ルール）** 4択の末尾が同じ言葉で揃うと、読者は4行を**読み比べ**ないと違いが分からなくなる。一文字コメントが押されるのは「**一秒で自分がどれか分かる**」ときだけ
  - **実例（8/25週 08-31）**：A〜Dが全部「〜を先に手放す」で終わり、違いは「諦め／焦り／目的／構え」という**抽象名詞の比較**だけだった。場面が浮かばず、選ぶのに読解が要る
  - 直し方は、選択肢を**読者の中の声**として書くこと。「話しても伝わらない、という諦めのほうを先に手放す」→「**もういい、どうせ伝わらない**」。語尾が自然にバラけ、そのまま自分の声として読める

### ルール3：締めCTAは「答えがコメントにある」と名指しする（2026-08-23 Coco決定・恒久ルール／**Threads診断のみ**）
**適用範囲＝Threads診断（2026-08-24 Coco決定で限定）。X診断は新形式の固定CTA「いちばん近いの、一文字だけコメントで教えて。」を使うため、本ルールの対象外**（X診断のコメント到達率は134%で、答えを見に行く行動が既に起きているため名指しが不要。詳細は本ファイルの「X診断の新形式」）。

実測（8/18週Threads診断）：本文43表示に対しコメント8表示＝**到達率18%、6日中3日はゼロ**。同週のXはnote添付コメントが本体の7〜9割読まれており、正反対。北極星「感情はある。依存はしない。」も会員導線もコメント側にあるため、**コメントが読まれない診断は、エンゲージメントにも収益導線にも接続しない**。
- 締めCTAは「A〜D、コメントへ」だけで終えない。**その回の答えがコメントにあることを、中身を名指しして添える**（一行・20〜35字目安）
- 型：「A〜D、いちばん近いのをコメントへ。〈その回の答えの名指し〉は、コメントに〈書いた／置いた／まとめた〉。」
- **名指しは中身まで**（「解説はコメントへ」のような一般語で終えない）。ただし答えそのものは書かず、飢餓感を残す
- **表現は毎回変える**（既視感ゼロチェック③と併走。7本で同じ言い回しを並べない）
- X診断の実測は揃った（到達率134%＝問題なし）。X診断は2026-08-24からの新形式に移行したため、本ルールはThreads診断専用として運用する

### `axis_map`（2026-08-30 追加・診断JSONの必須項目）

**選択肢を型に割り当てるのは「言葉の判断」なので、weekly が決める。**サイト側で推測させない。診断JSONの各 post に足す：

```json
"axis_map": {
  "A": {"temp": "高", "dist": "高"},
  "B": {"temp": "低", "dist": "低"},
  "C": {"temp": "低", "dist": "高"},
  "D": {"temp": "高", "dist": "低"}
}
```

- **4つの選択肢が4象限に1つずつ**入る。
- **同じ象限に2つ入ったら、まず軸の読み方を疑う**（2026-08-30 訂正。旧版は「選択肢のほうを直す」と書いていたが、**X診断は `CLAUDE.md` の絶対禁止で変更できない**ので、その道は最初から無い）。ずれ方はほぼ決まっている：
  - **距離は「自分の側か、相手の側か」ではない。「相手をどれだけ入れるか」**＝確かめて入れるか、確かめずに済ませるか。**不在の第三者の内心を推測するのは距離“低”**（入れていない）。**その場にいなかった責任まで引き受けるのは距離“高”**（関係を全部入れている）
  - **温度は「口に出すか、内側か」ではない。「感情をどれだけ出すか」。**自分を責めるのは、内側の作業でも**温度“高”**
  - この2つで読み直すと、たいてい4隅に割れる（2026-08-30、X診断 09-07 が実例）
- **それでも割れないときの順番**：①Threads診断なら選択肢を直してよい ②**X診断は直せないので、その回だけ8問診断の設問から外して報告する** ③どちらも本文（frame / choices / comment / reply_1）には手を付けない
- **日替わり4択に「中央（保つ人）」は割り当てない**（2026-08-30 Coco決定・恒久ルール）。中央は「4つのどれでもない」立ち位置なので、**1問しかない日替わりでは答えとして成立しない**。そして中央はCTAを出さない型なので、結果として出しても行き先がない。**中央が出るのは8問の合計スコアだけ**——8問の平均が真ん中に来たときにだけ意味を持つ
  - **旧実装（w6・w7）は「4隅のうち3つ＋中央(3,3)」で配点していた。**そのため4型ぶんの結果文が要る場所に3本しか対応せず、1択が結果を持てない状態だった。**9/1週（w8）から4隅に1つずつへ変更する**
- **`axis_map` は「記号 → 型」の対応そのもの。**サイト側の `DAY_ANSWER` は型キー（HH／HL／LH／LL）で引かれるが、weekly が持つのは選択肢キー（A〜D）。**両者を橋渡しするのが `axis_map` で、これが無いと結果画面は組み上がらない**（配点だけの話ではない）
- 温度＝感情をどれだけ出すか／距離＝相手をどれだけ入れるか（`rules/type.md` が正典。ここに定義を複製しない）
- **日替わり4択は8問診断の1問目**なので、`axis_map` は8問の配点と同じ物差しで付ける
- **無い回は、サイト側が止まる。**推測で埋めさせない

## X診断の新形式（2026-08-24 Coco決定・恒久ルール／#078〜適用）

**根拠は実測**：2026-08-18週のX診断はコメント到達率134%（本文211／コメント283・日別96〜170%）。同週のThreads診断18%と正反対で、X診断は「設問を読んで終わり」にならず、答えを見に行く行動が確実に起きている。**2通に分けると2通目まで読まれる保証がないため、答えを1通にまとめて確実に届ける。**

### 構成
| 要素 | 中身 |
|------|------|
| **本文（frame）** | その瞬間フック → 「四つとも、間違いではない。」→ A〜Dの選択肢 → 固定CTA → **間合い診断の一句** → `#温度の4択 NNN` |
| **固定CTA** | **「いちばん近いの、一文字だけコメントで教えて。」**（旧「いくつ当てはまった？」を置き換え） |
| **コメント（comment・1通のみ）** | もやもやの正体 → A〜Dの解説（**見るのは一点／明日の一手**）→ **結び（言い切り1本）** → ［該当回のみ］佇まいの一行 → **間合い診断への接続ブロック** → 「▼ 8問 / 約1分」→ 診断URL。**字数は「積まない」節が正典（接続ブロックより前を600字以内）。ここに数字を書かない** |

**旧構成の「締めの一段 → 3点まとめ → 結び」は、この3枠を「結び（言い切り1本）」に統合した**（2026-08-31 Coco決定・9/1週から）。
- **「3点まとめ」（番号リスト）は廃止。** 各選択肢の「明日の一手」の**そのままの再掲**になっていた（9/1週の実測で7本中5本、09-06は3行とも完全に同じ文）。読者は同じことを2回読まされ、約120字ぶん重くなっていた
- **「締めの一段」と「結び」で言い切りが2本立っていた。** 刃が2本あるとどちらも刺さらない（`rules/check.md`「六つの法則」一・六）
- **削るのは説明。「見るのは一点」と「明日の一手」は4つとも残す**——理由は上の「積まない」節。ここに複製を置かない
| **診断URL** | `https://shindan-flax.vercel.app/soshiki/MM-DD`（日付ごとに1ページ）。**コメントの最終行** |

### 廃止したもの（旧#077までとの違い）
- **comment_1 / comment_2 の2通構成 → comment 1通に統合**
- **バックカタログ行「これまでの診断：〜」を置かない**（蓄積感の提示は診断サイト側が担う）。ただし `shindan_series.json` の `technique_log` の更新は継続する（通し番号と過去テーマの台帳）
- **メンバーシップCTA・定番プロミスをコメントに置かない**。**会員導線は診断サイトの結果ページ側にある**（2026-08-24 Coco確認）。収益モデルとの整合はサイト側で取れているため、コメントに戻さない
  - **2026-08-30 追記**：結果ページが受ける先は、メンバーシップCTAではなく**その型の道案内note（無料）**に変わった（`rules/note.md`「入会後の『最初の3本』と、型別の道案内8本」）。**コメントに置かないことは変わらない**——変わったのは、コメントの外で受ける場所のほう
- **内省の問いを最終行に置く旧ルールは終了**（最終行は診断URL）
- **診断共通ルール3（締めCTAで答えの在り処を名指し）はX診断に適用しない**。Threads診断専用ルールとして運用する

### 字数は、言葉に合わせる（2026-08-30 Coco決定・恒久ルール／旧「280字上限に注意」を置き換え）

**削る順番を固定する。上から順に、絶対に削らない。**

| 優先 | 要素 | 幅 |
|---|---|---|
| 1 | **固定CTA**「いちばん近いの、一文字だけコメントで教えて。」 | 44 |
| 2 | **間合い診断の一句**（原文は「間合い診断への接続」節）＋直前の空行 | **30** |
| 3 | **選択肢A〜D** | 回による |
| 4 | **`#温度の4択 NNN`** | 14 |
| 5 | **その瞬間フック** ← **超えたらここから削る** | 回による |

**280を超えるとタイムラインで折り畳まれ、設問とCTAが初見で見えなくなり、診断そのものが成立しない。**

- **本体（一句を除いた全体）の上限は、上の「X診断｜本文（frame）は、本体を 249幅以内 で作る」が正典。ここに数値も計算も複製しない**（2026-09-01：一句が29→28幅に変わったとき、ここだけ旧計算のまま残った。2026-09-02：数値そのものも4箇所に増えていたので、この節はポインタだけにした）
- **旧版との違い**：旧版も「超えた回はフックを引き算して収める」だったが、**一句を数に入れていなかった**。あとから足す形では入らない——実測で 8/25週・9/1週の frame は **239〜271幅**、**249以内は7本中1本だけ**だった。**先に一句を置いてから、フックを削る**
- 数え方は**全角2・半角1・改行1**（`tools/shindan_check.py` の `width()`）。**生の文字数で見ると必ず読み違える**（130字＝約260幅）
- **`shindan_check.py` の判定は280のまま変えない**（`rules/check.md`「チェックの定義は、作った側が動かさない」）。249は生成時の自主上限
- 生成・グローアップのたびに**全7本を計測する**
