## 名前（2026-08-30 Coco決定・恒久ルール）

**正式名＝`Coco Methodology 間合い診断` ／ 通称＝「間合い診断」。**

- 説明の一行は「間合いの**調整**」ではなく「**あなたの間合いには、型がある**」。診断が映すのは調整法ではなく**いまのクセ**
- 「間合い」を選んだ理由：**温度と距離を1語で包む日本語**で、**職場にも恋愛にも自然に使える**（「上司との間合い」「好きな人との間合い」）＝**2本の柱を1語で串刺しにできる**。そして「間合いを間違えた」は読者が自分を責めるときの日常語なので、そこに型の名前を与えると**原理06（悩みの意味を反転して定義し直す）がそのまま効く**
- 既存の診断と軸が衝突しない：MBTI＝性格／ストレングス＝才能／動物占い＝生年月日／エニアグラム＝動機／**間合い診断＝人との距離のとり方**

### 差し替える4か所

**① 見出し（h1）**
```
関係の温度と距離を整える技術     ← 旧
あなたの間合いには、型がある。    ← 新
```
「整える技術」は**方法の名前**で、読者が知りたいのは「わたしは何型？」のほう。**新しい言葉ではなく、このファイルの「説明の一行」をそのまま持ってきただけ。**

**② リード**
```
うまくいかない原因は、熱意でも相性でもない。感情の温度と、相手との距離。
その2つの立ち位置にある。間合い診断は、そこに名前をつける8問。
```
最後の一文だけ足す（前半は現行のまま。比喩ゼロで既に成立している）。

**③ リードの下に一行（新設）**
```
「わたしはダメ」が、「わたしは溶ける人」になる。
```
**原理06（悩みの意味を反転して定義し直す）の実演**。このファイルの「型の名前は動詞人称にする」の理由説明で使っている例を、そのまま読者に出す。**効果を約束していない**——言い換えを見せているだけなので、CTAの禁止に触れない。

**④ 選択の一行**
```
どちらの温度と距離を、確かめますか                        ← 旧
どちらから、始めますか                                    ← 新
職場と家では、たいてい別の型が出る。8問 / 約1分で、ひとつ。両方で、ふたつ。  ← 新・補足
```
- **旧版は「1人が2つの型を持つ」と矛盾していた。** 「どちら**を**」は片方を選ばせる文。設計は両方やる

- **「ひとつ。両方で、ふたつ。」で完了が2回になる。** 入口の段階を増やさずに完了数を伸ばす唯一の形

### 欠落文は「型名の動詞と同じ絵」で書く（2026-08-31 Coco決定・恒久ルール）

**旧版の欠落文には4つ欠陥があった。上の表は書き直したあと。**

1. **二重否定**：「**欠けている**のは、自分の分が**残らない**ところ」——否定が2回で、論理としては同語反復。何が欠けているかを実は言っていなかった。**「欠けているのは」という枠ごと廃止した**
2. **絵が浮かばない**：「自分の分」は何の分か分からない（`rules/note.md` ②到達力「抽象語を避け、具体的に絵が浮かぶ言葉を使う」に違反）
3. **比喩が2本混ざる**：型名「溶ける」＝境目が消える絵／欠落「分が残らない」＝配分が枯れる絵。**別の絵**なので像が結ばない（`rules/check.md`「比喩の一本化」）
4. **💗側だけ磨かれていなかった**：💼は実装のほうが具体的だったので書き起こしたが、💗は「実装と4/4合致」だったのでそのまま残っていた。**合致していることと、良い文であることは別**。しかも**💗秘める人と💼こらえる人が完全に同じ文言**で、型が分かれていなかった

**書き方の原則**：①**型名の動詞と同じ絵**で書く ②**「〜人」で終える**（型名と文末が揃い、名乗りとして立つ）③否定は1回まで ④読者が絵を描ける具体語で書く。

**出し方**
- 記事の「この回の型」：`**〈型名〉**——〈座標〉間合い。**〈欠落文〉人**。`
- 道案内note：`問題は、やる気でも器でもない。**〈欠落文〉**。ただ、そこだけ。`

**⚠️ 診断サイト側（`Coco930118/shindan`）の結果画面がまだ旧版のまま。** 言葉の正典はこのファイルなので、サイトはここに合わせる（`reference/todo.md` に指示文あり）。

**「欠けているもの」はドメインごとに違う**（2026-08-30 訂正）。旧版は1列で両ドメインが共有する形だったが、**組織と恋愛は声が違う**（`rules/shindan.md`：温度＝組織は冷徹な軍師、距離＝恋愛は慈愛に満ちた哲学者）。実装と照合したところ**恋愛は4/4合致・組織は1/4**で、組織側は実装のほうが具体的だった（「渡せたはずの一件」「判断のほうを渡していない」「一度も情報を戻していない」）。**組織側3つは実装の文言を正として、2026-08-30 にここへ書き起こした**（旧「※実装から書き起こす」は解消）。

- **⚠️ 軸への割り当ては weekly 側の推定。** 実装から取ったのは3つの文言（「渡せたはずの一件」「判断のほうを渡していない」「一度も情報を戻していない」）で、**どれがどの型かは、恋愛側と並べて推定した**——高×高は引き受けすぎ（溶ける人／背負う人）、低×高は渡す側だが本体を渡していない（尽くす人／先に動く人）、低×低は閉じている（守る人／降りる人）
- **診断セッションが実装と1回照合して、違っていたら実装のほうを正として直す**（`reference/todo.md`）

### 記事を型に振り分ける手順（2026-08-31 Coco決定・恒久ルール）

**軸が2つあるのだから、振り分けも2回に分ける。1回で8型に当てようとすると、必ず熱量だけで割ってしまう。**

| | 何を見るか | 高 | 低 |
|---|---|---|---|
| **第1基準｜温度** | 感情をどれだけ出すか | 記事が扱うのは、読者の中で**感情が動いている／抱えている状態そのもの**（言いたい・我慢・淋しい・怒り・期待・不安・傷つく・引き受ける・認められたい） | 記事が扱うのは、**感情をすでに落として扱う**状態（書く・数える・訳す・順番・範囲・記録・見立て・段取り） |
| **第2基準｜距離** | 相手をどれだけ入れるか | 相手が場面に立っていて、読者が**相手に向かって動く／引き受ける** | 相手に出ていない／**自分の側で閉じている** |

- **順番を守る。温度を全部つけ終えてから、距離を重ねる。** 同時にやると「熱そうな記事＝高×高」に寄って、秘める人と尽くす人が混ざる（`rules/type.md` 上の注意「熱量で書き分けると2型が混ざる」の実務版）
- **第3基準は「最初の3本」（`principle_no`）。** 型が決まったあとに、受け止める（06・07）／整える（02・03・05）／動く（01・04）が各型で埋まるかを見る
- **判定の根拠は `maai_axis`（`{"温度":"高|低","距離":"高|低"}`）として各JSONに残す。** 残さないと、次のセッションが別の基準で振り分けて棚が混ざる
- **型を持たない記事がある**（`plan_type: null`）：常設案内・週次の無料まとめ・土台記事。**読者の立ち位置ではなく場所の説明をしている**ので、型マガジンではなく無料マガジンに入る
- **枠が埋まらないとき、先に疑うのは本文ではなく `principle_no`。** 実測（2026-08-31・83本）：空いた2枠はどちらも本文ではなく、原理の記載が本文とズレていたのが原因だった。**記事が実際にやっていること**（渡している処方・立てている現実）に合わせて直すと埋まる。本文を書き直す前に、必ずここを見る
- 実測（2026-08-31）：78本を振り分けて8型すべてに記事が入り、24枠（8型 × 3ステップ）が全部埋まった。**在庫の偏りは 💗秘める人19本 ↔ 💼降りる人3本**。薄い型は、既存を直すのではなく**書く先を型で決めて埋める**

### 読者に「10型」と言わない（2026-08-30 Coco決定・恒久ルール／weekly内部の食い違いを解消）

**「10型」は内部の数え方**（4型 × 2ドメイン ＋ 中央2）。**読者に出す数字は別。**

| | 数え方 | どこで使う |
|---|---|---|
| **内部** | **10型** | このファイル・実装・設計の議論 |
| **読者に出す** | **ドメインごとに4つ＋保つ人**／**組み合わせは16通り** | 診断ページ・投稿・OG画像・シェア文 |

- **理由**：中央は両ドメインとも同じ「保つ人」なので、**読者から見える名前は9つしかない**。「10型」と言うと数が合わない
- **`rules/shindan.md`「『型は10』と書かない」は、この読者向けの数え方のこと**。内部の10型と矛盾しない
- **OG画像の「4タイプ」は誤りではない**（ドメイン内の4型を指している）。中央を含めて書くときだけ「**4つの型＋保つ人**」にする
- **いちばん強い数字は16通り**（`reference/todo.md`：MBTIの拡散は「16のうちの1つ」という希少性が効いている）。**単型4つでは「あるある」になる**

**出現率（%）はここに置かない**（2026-08-30 削除）。旧版は中央の定義が `|Δ|≦1` だった頃の理論値で、閾値を変えるたびに古くなる。**理論分布は判断に使えない**（`CLAUDE.md`「実測でしか配分を変えない」）。分布を見るなら KV の実測を読む。

- **高×低 と 低×高 は、熱量の差ではなく「相手がいるか・渡すのが自分の判断か」で割る。** 熱量で書き分けると2型が混ざる
- **1人が2つの型を持つ**（恋愛の型 × 組織の型）。これはMBTIにない構造で、根拠は `coco_methodology.json` の読者定義「一件片づいても終わらない。**職場と家で同時に走る**」。名乗り文は「**恋愛は溶ける人／仕事は降りる人**」

### 名乗りは2行で出す。型は組み合わせで効く（2026-08-30 Coco決定・恒久ルール）

**「1人が2つの型を持つ」は、設計の説明であると同時に、シェアの単位。** 単型のままだと、この構造がどこにも出ていない。

- **単型（4通り）は「あるある」になる。** 読者の1/4が同じ名前なので、シェアされても埋もれる
- **組み合わせ（4×4＝16通り）で、はじめて「わたしだけ」になる。** 自分と同じ組み合わせにめったに会わない。**16は境界線**——少ないと自分だけ感が出ず、多いと名乗れない
- だから**結果のシェア文は2行名乗りを基本形にする**：「恋愛は**溶ける人**。仕事は**降りる人**。」＋ **その組み合わせにしか出せない見立ての一行**（例：出すのが止まらない人が、出さないほうを選んでいる）
- **単型の一行を2つ並べただけにしない。** 並べただけなら、組み合わせにする意味がない
- そのために、**型が出た読者全員に「じゃあ、もう片方は？」を置く**（従来は中央「保つ人」だけの扱いだった。下の「「保つ人」（中央）の扱い」を全型へ広げる）。**1人あたりの診断完了が2回になる**ので、入口の段階数を増やさずに完了数が伸びる
- **順番を守る。主導線は型の道案内note（`rules/note.md`）で、「もう片方は？」はその下の副次導線。** 逆にすると、せっかく出た型が会員導線に繋がらないまま次の診断へ流れる
- 16通りの見立て一行と、型別OG画像の整備は診断サイト側の持ち場（`reference/todo.md`）。**言葉はここで作ってから渡す**


### 型の名前は動詞人称にする（2026-08-30 Coco決定・恒久ルール）
- **キャラ名（しずく型・しらたま型・ひより型）を型の名前にしない。** 型の名前は**動詞人称**（溶ける人・こらえる人・降りる人…）で固定する
- 理由3つ：①動詞人称は**痛みを名指ししている**ので「それ私だ」が立つ ②キャラ名は自己認識が立たない ③**原理06の反転が効くのは動詞のほう**——「わたしはダメ」→「わたしは溶ける人」は反転になるが、「わたしはしずく型」は反転にならない
- **旧案「ブレンド型」は不採用**（血液型のABを模した中間型）。AB型が成立するのは**A・B・Oが先に全員へ浸透しているから**で、新規の診断では中間型は最初から「どっちつかず」と読まれる。実装の「**保つ人**」は名乗れて否定的でないので、こちらを採る
  - **「ブレンド型」の語が読者に出ている箇所は「保つ人」に置き換える**（2026-08-30・実装の共有文とバッジに残存）。**これは新しい言葉づくりではなく、正典にある語への置き換え**なので、サイト側で実施してよい

### 中央（保つ人）にCTAを出さない（2026-08-30 Coco決定・恒久ルール／実装が違反中）

**実装は `CENTER.cta` でメンバーシップCTAと料金表を出している。**`CLAUDE.md` とこのファイルの「CTAを出さない」に反する。中央は**まだ型が定まっていない人**なので、そこへ課金を出すと「どっちつかずの人に売る」形になる。

- **まず出さないようにする**（ブロックごと非表示）。これは削除なので、言葉づくりを待たずにサイト側で実施できる
- 代わりに置く「**もう片方のドメインへ送る**」の文言は、weekly が作って渡す（診断セッションの持ち場）。**届くまでは空でよい**

| **見立てる** | **Coco** | 型を名指しする。結果画面の「核（punch）」がこの声 | 変わらない |
| **立ち位置** | **型**（動詞人称） | 読者が名乗るもの | 変わらない |
| **関わる** | **3匹** | 型から動くために、いま要る声 | **変わる（毎週更新できる）** |

- **3匹は「型」ではなく「声」に当てる。** 型は10（4型×2ドメイン＋中央2）でキャラは3匹なので、**1:1に当てるのは構造的に無理**
- **禁じるのは2つだけ**（2026-08-30 精密化。旧版は「キャラを型に固定しない」とだけ書いていて、実装のバッジまで違反に読めた）
  1. **キャラ名を型の名前にしない。**名乗るのは動詞人称（守る人・降りる人…）。原理06の反転が効くのは動詞のほう
  2. **処方の3ステップで、型に紐づいた1匹だけを出さない。**受け止める→整える→動くは3匹で1セット。1匹に減らすと処方が1/3になる
- **型に代表キャラを1匹添えるのはよい**（結果画面のバッジ「守る人／しらたま型」の形）。型名は動詞人称のままで、キャラは**添え物**。禁止の1にも2にも当たらず、**シェアされる絵として資産になっている**（結果シェアは出口の本体・`reference/todo.md`）

### 3匹は、処方の3ステップ（元のキャラ設計がそのまま七つの原理に対応する）

| 順 | キャラ | 担当ステージ | 対応する原理 | 代表の声 |
|---|---|---|---|---|
| 1 | **しらたま** 🐈‍⬛ | 自己受容・感情ケア | **06**（意味を反転して定義し直す）・**07**（現実を先に置く） | 「だめだなって思える日は、やさしくなるチャンスかも。」 |
| 2 | **しずく** 🐢 | 内省・整える | **02**（悩みを消さない、扱えるようにする）・**03**（事実と感情を分ける）・**05**（三つ目の軸） | 「答えはね、静かな時間の中にあるよ。」 |
| 3 | **ひより** 🕊 | 選択・飛び立つ | **01**（今日決められることを一つ）・**04**（決断を相手に返す） | 「正解じゃなくて、"いま選びたい方"でいいんだよ。」 |

**受け止める（しらたま）→ 整える（しずく）→ 動く（ひより）。** この順番を入れ替えない。

#### 型に添えるキャラは、その型に「いま要る声」で決める（2026-08-30 Coco決定・恒久ルール）

| 型（欠けているもの） | 要る声 | キャラ |
|---|---|---|
| 溶ける人／背負う人（**引き受けすぎ**） | 責めない・意味を反転（06・07） | **しらたま** |
| 秘める人／こらえる人（**届いていない**） | 事実と感情を分ける（02・03） | **しずく** |
| 尽くす人／先に動く人（**自分がいない・判断を渡していない**） | 選ぶ・決断を返す（01・04） | **ひより** |
| 守る人／降りる人（**閉じたまま動かしていない**） | **責めない（06・07）** | **しらたま** |

- **守る人・降りる人は「しらたま」**（2026-08-30 Coco決定）。**閉じている自分を責めている人に、まず要るのは受け止める声**だから。タグが「自分で決められる型」なので一度ひよりに変えたが、**Cocoの判断で戻した**——**タグは型の説明で、キャラは読者にいま要る声。この2つは別**
- **キャラは「型の説明」に合わせない。「読者がいま何を必要としているか」に合わせる。** ここを取り違えると、正しく見えて効かない配役になる
- **ただし禁止「3匹の担当ステージを越えた声を書かない」は守る。** 旧実装のしらたまの声は「**降りるのも判断だ**」で、判断＝原理04＝ひよりの担当だった。**キャラはしらたまのまま、声を受け止める側へ書き直した**（「降りた日も、ここにいていい。決めたのは、あなただよ。」）
- **しらたまが1ドメインに2回出るのは、偏りではなく設計**（引き受けすぎ／閉じている、どちらも「まず責めない」が要る）

---|---|---|
| 溶ける人／背負う人（**引き受けすぎ**） | 責めない・意味を反転（06・07） | **しらたま** |
| 秘める人／こらえる人（**届いていない**） | 事実と感情を分ける（02・03） | **しずく** |
| 尽くす人／先に動く人（**自分がいない・判断を渡していない**） | 整える（03・05） | **しずく系だが実装はひより**（※下記） |
| 守る人／降りる人（**閉じたまま動かしていない**） | **今日決められることを一つ・決断を返す（01・04）** | **ひより** |

- **守る人／降りる人は「ひより」。** 2026-08-30 まで実装が「しらたま」だったが、**タグが「扉を開ける時を、自分で決められる型」「降りると決められる型」で、決める＝原理01・04＝ひよりの担当**。しかも**欠けているものが「閉じたまま動かしていない」**なので、要るのは受け止める声ではなく動く声
- **禁止「3匹の担当ステージを越えた声を書かない」に触れていた。** 旧実装のしらたまの声が「**降りるのも判断だ**」（＝原理04）だった。判断はひよりの担当
- **しらたまが1ドメインに2回出ていた**（引き受けすぎ＋閉じている）。**引き受けすぎのほうだけがしらたま**3匹は最初から七つの原理の3段階だった——**新しく作った対応ではなく、元のキャラ設計に既にあったものを言語化しただけ**。

- 3匹とも「**無理に励まさない／否定しない／静かに支える**」（元の設計より・恒久）
- 声の文言は元のキャラ表（感情・状態→一言）を土台にする。**新規に書くときも、そのキャラの担当ステージから出ない**
- **画像は従来どおり Coco＋動物**（`rules/image.md` が正典。動物の7周期・アングルの5周期はそのまま。型に合わせて動物を選ぶ運用は、巡回の均等が崩れて `full_check.py` が落ちるため、**入れるなら実測とツール変更をセットでCocoに提案する**）

## 「保つ人」（中央）の扱い

**CTAを出さない。** 処方を渡せない相手に売らない——この判断は維持する。

- **ただし行き止まりにしない。** CTAの代わりに、**もう片方のドメインへ送る**（恋愛で保つ人だった人は組織で受ける／逆も同じ）
- 売り込みにならず、**1人が2つの型を持つ設計をそのまま活かせる**

  - **これは35投稿（X14・Threads21）についてのルール。** note側は別に持つ（`rules/note.md`「週のfunnel note 8本は、4型を全部カバーする」）。**片方を根拠にもう片方を省略しない**（2026-08-31 追加。道案内noteの約束を35投稿のルールで担保しているつもりになっていた）

- 締めや〈ひとこと〉に型名を書く必要はない。**型は書き手が狙いを外さないための軸**であって、毎回名乗らせるものではない

### 型の一行タグは、SNSに出してよい（2026-08-30 Coco決定・恒久ルール）
結果画面の**一行タグと核（punch）は、いまのリポジトリで最も強いコピー**。4クリックの先に置いたままにしない。
