作り終えたあとに回す。**機械にできることは機械に。目で見るのは下の8つだけ。**

## 1. 機械チェック

```
python3 tools/full_check.py    posts/week_*.json            # 35投稿
python3 tools/shindan_check.py posts/shindan_*_YYYY-MM-DD.json   # 診断14本
python3 tools/note_check.py    --week YYYY-MM-DD_YYYY-MM-DD      # note＋約束と回収の突き合わせ
python3 tools/episode_check.py --week YYYY-MM-DD                 # E373素材の週内カウント（35投稿・診断・note横断／Wチェックで回す）
python3 tools/profile_check.py                                   # 各媒体のプロフィール文面（Wチェックで回す）
python3 tools/canon_check.py                                     # 正典がひとつか（ルールを直した回は必ず／CLAUDE.md「正典はひとつ。復唱しない」）
```

### プロフィールは、どのツールの対象でもなかった（2026-09-02 Coco決定・恒久ルール）

**いちばん人目に触れる4行が、一度も検査されていなかった。** `full_check` は `posts/`、`note_check` は `notes/`、`shindan_check` は診断、`episode_check` は素材しか見ない。**`reference/brand_profile.json` の `profile_text` を開くツールが1つも無かった。**

- **実測（2026-09-02）**：Xのプロフィールに**禁止語が2語**（「心理的距離感の**設計**士」「▼**渡し**方の**設計**は note に」）。手で読んで初めて見つかった
- **禁止語の定義は `full_check.py` からインポートする。`profile_check.py` に複製を置かない**
- 運用対象外の媒体（`in_scope: false`）は検査しない。判定は `brand_profile.json` の `meta` が持つ
- **数字の表記を見る。** 正しい表記も、誤りの一覧も `CLAUDE.md`「使える数字は4つだけ」が正典（機械が持つのは `profile_check.py` の `NUM_NG`）。**ここに複製を置かない**——2026-09-02、この行は「複製を置かない」と書きながら誤り4語をそのまま並べていた

**媒体をまたぐ検査は2つだけ**（2026-08-31 明記）。`note_check.py --week` が**約束と回収**（35投稿 ↔ note）を、`episode_check.py --week` が**素材の重複と生活描写**（35投稿 ↔ 診断 ↔ note）を見る。この2つ以外は自分のファイルしか読まないので、**媒体をまたぐ指摘をそこに期待しない**。

毎回その場でスクリプトを書かない（項目がブレて抜けるため）。**項目を足したくなったら、その場しのぎで書かずツール本体を更新する。**

`note_check.py` は `--all`（index掲載の全note）とファイル名の直接指定も受ける。

### E373素材の週内カウント（`episode_check.py`・2026-08-29 Coco決定・恒久ルール）
**媒体をまたぐ素材の重複は、他の3ツールでは構造的に検出できない**（どれも自分のファイルしか読まない）。E373の `usage_limit`「同じ要素は週内1回まで」は媒体を問わないので、**Wチェックで週1回、全媒体横断で数える**。
- **対象は 35投稿・診断14本・その週のnote全部**（`source_week` がその週のもの）。**noteを対象に入れたのは 2026-08-31 Coco決定・恒久ルール**——「媒体を問わない」と書きながら、ツールは `posts/` の3ファイルしか開いていなかった。**noteも媒体**
- 検出語をツールに手で持たせない。**素材の正典は `reference/episodes_soshiki.json` の E373 の `elements` だけ**（`tools/e373.py` が読み、`full_check.py`・`shindan_check.py` の `WIT_HINTS` もここから生成する）
- **要素を足すときは台帳の `key_phrases` と `elements` を直す。ツールは触らない**
- 検出後の判定は目視（ツール末尾の判断チェック）。特に**主語の線引き**——習慣の形ならE373に限る／ゼロ主語なら限らない（`rules/posts.md` ルール4①）
- **noteに差し込む生活の一行も、E373の要素だけで書く**（2026-08-31 Coco決定・恒久ルール）。ツールは「〜するのも、〜」「〜くらいでちょうどいい」の**提案形**だけを拾い、E373の要素を含む／含まないで分けて出す。含まない行は素材外の創作を疑う
  - **枠に固有の構文だけを見る。** 最初は「1文だけの短い段落」で拾ったが、note 8本で47件当たった（定番プロミスも背中押しも冒頭の一行も全部かかる）。過検出は、下の「ツールに合わせて本文を書き換えたら、それは欠陥の報告」が警告している状態を自分で作る
- **背景**：2026-08-29に3件同時に出た。①E373にベランダ・昼寝を足しても検出が増えない ②E373に無い「湯船」を正解として検出し続けていた（2026-08-27に直した違反をツールが推奨し返す状態）③9/1週の「花」がX診断9/3とth_15 9/5で二重に使われていたのが、手で数えて初めて見つかった
- **2026-08-31に4件目**：note に「駅のホームでただぼーっとする」「近所のパン屋さんが閉まる前に行ってみる」——どちらもE373に無い生活描写だったが、**ツールが notes/ を開いていないので誰にも検出できなかった**。穴が空いていたのは書き手ではなく検査の側

### 禁止語は「語」ではなく「動詞」で持つ（2026-08-31 Coco決定・恒久ルール）
**終止形だけを文字列で並べると、活用形が素通りする。書き手は活用して書くのだから、検出も活用形まで見る。**
- **定義は `full_check.py` が1箇所で持ち、他の3ツールはインポートする**（2026-09-02 統一）。3ツールが自前でコピーを持っていたため、**実際に片方だけ古くなった実績がある**（「大切なのは」が `note_check.py` にしか無く、2026-08-29 に補完）
- `渡す／渡し` は `渡[すしせさそっ]` として持つ（渡す・渡し・渡せる・渡さない・渡そう・渡って）。`full_check.py`・`shindan_check.py` は要修正、`note_check.py` は参考カウントのまま（この線引きは変えない）
- **実例（2026-08-31 Wチェック）**：9/1週 x_09「渡**せる**」／X診断 09-06「渡**っ**ている」が、どちらも要修正のまま無検出で通過していた
- 禁止語を足すときは、**活用する語かどうかを先に決める**。活用するなら正規表現、しないなら文字列

### note（`note_check.py`）
禁止語（原理01/07の公式文言と、「」内の引用＝読者の声・過去記事タイトルは例外。**「渡す／渡し」は活用形まで数えたうえで、要修正ではなく参考カウント**——`rules/note.md` 参照）／一人称の「私」（記事タイトルの引用は例外）／md と html の同期／プラン記号（💼💗・二重も）／定番プロミスと本数の約束／**約束と回収の突き合わせ（`promise_map`・下記）**／冒頭の型の名乗り／在り方署名→背中押し→あわせて読む→型で、続けて読む→メンバーシップCTAの順／**本文の最終行がメンバーシップURLか**（`rules/note.md`「本文の最終行は、メンバーシップURL」）／有料エリアの境界と `free_ratio` の実測一致／販売リストが有料側に埋まっていないか／単発有料の検出／あわせて読むのプラン跨ぎ／画像プロンプト（1280x670・Canva禁止語・early thirties・No text・中央3分の1・短縮版・季節モチーフと公開月）／週内の重複（背中押しの言い切り・在り方署名の書き出し・あわせて読むの導入文）。

### 約束と回収を突き合わせる（2026-08-31 Coco決定・恒久ルール）

**funnel投稿の返信2で約束したものを、noteが本当に書いているか。ここが週次でいちばん高くつく穴だった。**

読者は約束を読んで有料の壁を越える。**約束の半分しか無いnoteは、返金されない不履行**であって、体裁の問題ではない。しかも3つのツールはどれも自分のファイルしか読まないので、投稿とnoteをまたぐこの穴は**構造的に検出できなかった**。

- **`promise_map` の形は `rules/note.md`「約束したものを、見出しで回収する」が正典。ここに複製を置かない**（`rules/ops.md`「noteJSONの構造」にフィールドの定義がある）
- **機械が見るのは構造だけ**——①約束したnoteが在るか ②`promise_map` が在るか ③キーの集合が投稿の約束と一致するか ④値の見出しが本文に実在するか。**意味の回収は目視**
- **書かせること自体が空手形を止める。** 回収した見出しを名指しできないなら、回収していない
- **実例（2026-08-31 Wチェック・9/1週）**：funnel 8本のうち**4本**が約束の半分を書かずに公開待ちだった。th_03「追いたくなった日の戻り方」なし／th_07「逆にしてしまった時の立て直し」なし／x_10「来週の一手に変える」なし／th_06 は「翌朝の**伝え直し方**」と約束したのに、noteは「相手に見せるためではない」と**正面から否定**していた
- **約束は投稿側が正典。** ぶつかったら投稿の返信2を直すか、noteを足すか。**先に決めるのは「どちらが読者にとって正しいか」で、書き直しやすいほうではない**

## 2. 目で見る8つ

**機械では見られないものだけ。** ツールの末尾の出力を使って埋める。

**`full_check.py` の【判断チェック】が、この8つの枠をそのまま出す（2026-08-31 Coco承認）。** 出るのは**枠と材料だけで、条件は出ない**——判定はこのファイルを見て行う。**ツールに条文を書き写さない**（複製は必ず片方が古くなる）。型名は `rules/type.md` から実行時に読むので、正典を直せばツールが追随する（`tools/maai.py`。素材を台帳から読む `tools/e373.py` と同じ形）。
- **旧版は①②③の3ブロックしか出しておらず、⑤型の充足・⑥数字の全数照合・⑦質問候補・⑧抽象語の置き場所が出力に無かった。** ルールはあるのに実行の入口が無い状態で、**9/1週の35投稿に型が1つも残っていなかったのと同じ経路**。ルールを直すことと、実行されるようになることの間には、まだ1段ある
- **これは判定条件の変更ではない**（「チェックの定義は、作った側が動かさない」に触れない）。**機械チェックの検出条件・要修正の件数・終了コードは1つも変えていない。** 変えたのは、目視項目に材料を添えたことだけ

1. **処方の言い換え重複** — 35本の処方を一行ずつ書き出して並べ、**言葉を変えただけの同じ処方が3本以上ないか**。語の検索では検出できない（実例：「自分の予定を先に入れる／週末を空けない／会う前後に一人の時間を挟む／日曜朝に自分の席を取る」の4本が、語は全部違うのに処方は同じだった）
2. **原理と型の配分** — **下の6項目チェック⑤を回す**（原理01〜07の割り当てと偏り、週内で4型がそろっているか）。ここには手順を複製しない（2026-08-31：⑤と同じ検査がここにも書かれていて、⑤にだけ型を足すと**こちらが古い版として残る**形だった）
3. **比喩の一本化** — **下の「35投稿完成後の6項目チェック」③比喩一本化プロトコルを回す**（切り分けは「六つの法則」の一・五・六）。ここには手順を複製しない（2026-08-30：同じ検査が2箇所にあり、別物なのか同じものなのか読んだ側が判定できなかった）
4. **8割読み切り** — **下の6項目チェック⑥-3を回す**（ターゲットの8割が読み切って「なんだか心が整理された」が残るか）。ここには複製を置かない
5. **ブランド整合性** — **下の6項目チェック⑥-1を回す**。ここには条件を複製しない
   - ⚠️ **旧記述の括弧「商品名の枠内か／X＝組織の「温度」・Threads＝関係の「距離」／売っているのが在り方（Being）か」は削除した**（2026-09-03）。**3つとも、⑥-1が名指しで否定した旧版の判定基準だった**——①商品名で合否を出さない（2026-08-31）②軸で媒体を分けない（2026-08-31）③Beingは書き手の内側の軸で、読者に出す売り物の言葉ではない（`CLAUDE.md` 3層表）。**「ここには複製を置かない」と書いた行が、その隣で旧版を3つ復唱していた**

6. **数字は全数を素材と照合する（2026-08-27 Coco決定・恒久ルール）** — 本文にある**経過・回数・期間の数字を1つ残らず**、`episodes_soshiki.json` の割当エピソードと突き合わせる。素材に無ければ落とすか、伝聞マーカーで相談者に帰属させる
   - **機械はここを1〜2割しか拾えない。** 実測（2026-08-27）：`full_check.py` の検出5本に対し、目視では**39本**（8/25週22本・9/1週17本）が素材の裏づけなしに数字を書いていた
   - **理由**：機械は語の有無しか見られない。**素材にその数字があるかは、在庫を読んで意味を照合しないと判定できない。** だから目視項目に置く。機械の検出は「明らかなものを拾う網」であって、通ったことの証明にはならない
   - 落とした場合は「来た／来なかった」の両方提示だけで閉じる。それで足りる

7. **Cocoへの質問候補を出す（2026-08-27 Coco決定・恒久ルール）** — 他の項目で見つけたもののうち、**素材が足りなくて直せないもの**を、Cocoへの質問**3件まで**にして出す。作法は `CLAUDE.md`「Cocoへの質問の作法」。**ここに条件を書き写さない**（2026-08-31：この括弧が作法の一部だけを持っていて、同日追加の「関連投稿の全文を貼る」「粒度の見本を先に書かない」が落ちていた）
   - **聞くのは、通しで読んだ後。生成の前ではない。** 穴は、埋めようとして初めて見える。先に「他にどんな締め方がありますか」と聞いても抽象的すぎて答えられない。「締めが2つの型に収束している」と分かって初めて、聞くべきことが決まる（実例：2026-08-27に締めの型③④⑤＝E407〜E409をこの順序で引き出した。それ以前は①②しか無く、65本が1つの骨格に収束していた）
   - 出した質問と回答は、素材として `episodes_soshiki.json` に登録してから未配信分に反映する
   - **聞く前に、在庫に無いことを確かめる（2026-08-27 Coco決定・恒久ルール）。** `episodes_soshiki.json` を検索して、その要素が本当に無いかを見てから質問する。**在庫にあるのに聞くと、Cocoの手を止めるだけになる**
     - 実例：2026-08-27のWチェックが「E373は外出の素材が中心で、家で過ごす日の要素がない」として家の過ごし方を質問したが、**E373には「映画／昭和ドラマ／ヨガ・ピラティス」が既にあった**（9/7のX診断で使用済み）。本当の問題は「家の素材がない」ではなく「**E373に無い生活描写（シーツ・湯船、および当時E373に無かったベランダ・昼寝）を書いていた**」ことだった
     - **「素材が足りない」と「素材と違うことを書いた」は別の指摘。** 前者は質問、後者は在庫の要素への置き換えで済む。取り違えると、要らない質問がCocoに飛ぶ
     - **ただし在庫がゼロのときは、この二つを区別できない**（2026-08-31 Coco決定・恒久ルール）。置き換える先が無いので、書いてあるものが「足りない」のか「違う」のかは、Cocoに聞かないと分からない。その場合は**「素材不足」として、関連投稿の全文を貼って聞く**（`CLAUDE.md`「Cocoへの質問の作法」）

8. **抽象語の置き場所（2026-08-30 Coco決定・恒久ルール）** — `rules/posts.md` ルール6。**冒頭2行・処方の起動条件・〈ひとこと〉に、その投稿内で定義していない語がないか**を1本ずつ見る
   - **壊れ方は下の「六つの法則」の二・三・四で切り分ける。** 2026-08-30 の3本はこの3つに1本ずつ当たった
   - **機械化を試して、見送った（2026-08-30 実測）。** 〈ひとこと〉の語が本文前半にあるかを数えると、**35本中25〜32本が当たる**（「責」「引」「直」のような語幹で切れるため）。どの語が概念を担っているかは意味を読まないと判定できない
   - **だから人が読むしかない。** 2026-08-30 にCocoが挙げた3本（8/25週 th_15・x_07・x_10）は、**機械チェックも目視項目も全部通っていた**
   - 見つけたら、新しい言葉を探さず**その投稿が後で使っている具体語を前に出す**（素材の追加は要らない）

**報告するときは、機械で確認した項目と、目で見た項目を分けて書く。目視していない項目を「クリア」と書かない。**

### 同じ節を2回以上書き直したら、その節を通しで読み直す（2026-08-27 Coco決定・恒久ルール）

**ルールを書き直すと、古い版が残る。** 書き直した本人は「良くなった」としか思っていないので気づけない。

- **同じ節に2回目の変更を入れたら、変更部分ではなく節の全文を読み直す。** 見るのは3つ——**①同じ段落が2回入っていないか ②古い⭕と新しい❌が食い違っていないか ③例示が最新形になっているか**
- **実例（2026-08-27）**：note案内の節を1日で3回書き直した結果、①ブロックが丸ごと2回入り ②同じ表現が上では⭕で下では❌になり ③パレット4型の見本が最新形を守っていなかった。**上から読むと必ず間違える状態**だったが、Cocoに聞かれるまで誰も気づいていない
- **機械で拾える**：手順と限界は下の「全媒体ルールは CLAUDE.md にだけ置く」の**検査**にまとめてある（完全一致しか拾えない点も含む）。②③は目視

### ルールを直したら、その数字と方針の出どころと行き先をたどる（2026-09-02 Coco決定・恒久ルール）

**方針の正典は `CLAUDE.md`「正典はひとつ。復唱しない」。ここが持つのは手順とツールだけ。**

**上の「同じ節を2回以上書き直したら」は節の内側を見るルール。これは節の外側を見る。** 1回目の変更でも回す。

**たどるのは2方向。**
- **上流**：その数字の根拠になった実測は、まだ生きているか（**根拠にした本文が変わっていないか**）
- **下流**：その数字・方針を根拠にしている場所は、追随したか（**別の節・別のファイル・ツール・検査表・指示文**）

**見るのは5つ。どれも実際に腐った形。**

| # | 何が | 実例（2026-09-01〜02） |
|---|---|---|
| 1 | **実測値**。根拠にした本文が変わると腐る | `reply_1` を「436〜512字だから足す余地がない」と書いた後、ラベルに畳んで364〜428字になったのに、数字が3箇所で旧いまま |
| 2 | **計算式**。部品の値が変わると腐る | 「280 −（一句**29**＋空行2）＝249」。一句を28幅に変えたのに、別の節の計算だけ残った |
| 3 | **見出し**。中身を足すとずれる | 見出しが「折り畳み位置（280幅）まで…」なのに、中身に全体の上限350字も入っていた。**探した人が飛ばす** |
| 4 | **否定した旧指示**。残ると⭕と❌が並ぶ | 上の節が「『元の下書きの半分以下』は測れないので機能していなかった」と否定しているのに、否定された当の指示が下の節に残っていた |
| 5 | **方針**。一方だけ変えると割れる | 禁止語を `profile_check.py` だけインポートにして、他3つは自前コピーのまま。**いま値が同じでも、次に足したとき割れる** |

**手順**
```
python3 tools/canon_check.py                # ①否定した旧指示の生き残り ②数値の二重持ち ③近い文の復唱
git show --stat HEAD                        # 何を触ったか
git show HEAD | grep -E '^[-+].*[0-9]'      # 動かした数字
grep -rn "<その数字>" CLAUDE.md rules/ tools/ reference/   # 下流に何箇所あるか
```
**1箇所より多く出たら、そこが腐る予約。** 数値の正典を1つ決めて、他は参照に変える。

- **`canon_check.py` は候補を出すだけ。判定は目で決める**（片方が正典・片方がポインタなら正しい形）。`--ghost` `--num` `--echo` で1つずつ回せる
- **拾えないもの**：表の中の数字・見出しと中身のずれ・言い換えた方針。**だから機械のあとに人がたどる**
- **実測（2026-09-01〜02）**：2回の点検で見つけた**11件のうち9件**が「**その回の変更が置き去りにしたもの**」だった。**外から来た違反より、自分の変更が作る欠陥のほうが多い**
- ⚠️ **②は一度、検出力ゼロで書いた**（2026-09-02）。過検出を潰そうと条件を重ねた結果、**その日の実物を再現しても0件**になっていた。**動かないチェックは、安心だけ配ってこのルールを邪魔する。** 検査を足したら、**直した実物で一度は鳴らしてみる**
- **報告に書く。** 何を直し、その数字と方針をどこまでたどったかを一行で残す。**たどっていないなら「たどっていない」と書く**（`rules/check.md` 冒頭「目視していない項目を『クリア』と書かない」と同じ）

### 全媒体ルールは CLAUDE.md にだけ置く（2026-08-29 Coco決定・恒久ルール）

**方針の正典は `CLAUDE.md`「正典はひとつ。復唱しない」。ここが持つのは、どのファイルに置くかの割り振りと、検査の射程だけ。**

- **文体・特定回避・創作の境界・使える数字のような全媒体ルールは `CLAUDE.md` にだけ置き、`rules/*.md` からは参照する**（「`CLAUDE.md`「文体」が正典」と書くだけにする）
- 媒体固有のルールは、その媒体の `rules/*.md` にだけ置く
- **検査の射程は `CLAUDE.md` ＋ `rules/*.md` ＋ `reference/*.json`（2026-08-31 Coco決定・恒久ルール／射程を広げた）**

  - **`reference/*.json` は「毎回読む」「最上位」を名乗るものほど危ない。** 優先順位が高いファイルの古い条文は、正典より強く読まれる

### チェックの定義は、作った側が動かさない（2026-08-27 Coco決定・恒久ルール）

**`tools/*.py` の検出条件を、そのチェックを受ける側（生成・グローアップ・編集のセッション）が変更しない。** 変更の権限はWチェック側に集める。

- **ツールが間違っていることは実際にある。** その場合も自分で直さず、**Wチェックに差し戻す**（実例：2026-08-27、締めの骨格の窓が note導線行を1本として数えており、funnelだけ締めより1行手前を測っていた。これはツール側の誤りで、Wチェックが修正した）
- **禁止ではなく、権限を1箇所に集める運用。** 定義が2箇所で動くと、申告値そのものが揺れて比較できなくなる
- **理由**：2026-08-27に定義が2回動いた。①編集側が funnel検出を「ただし」だけに狭めた（「ただ、」は接続詞で実装ではない、という理由だったが、結果として自分の書いたものが通るようにチェックが緩んだ。編集側が自己申告して発覚）②窓の定義（上記）。どちらも悪意ではなく、**定義が曖昧なまま機械化したために起きている**
- **用量の申告は、ツールの数字を上限として扱う（2026-08-29 Coco決定・恒久ルール）。** ツールが出すのは「候補」で、**目視の実数がそれを超えることはない**。下げるときは、外した1本ずつに理由を書く
  - **危険は両側にある。** 上げる方向＝自己申告が甘い方向にずれる（`reference/decisions.md`「自己申告は甘い方向にずれる」）／下げる方向＝機械が語の一致だけで過検出する（`rules/posts.md` ルール4①の「数えない①②」）。**上限＋理由つきの減算**で両方を止める
  - 旧「`full_check.py` の出力をそのまま使う」は廃止（2026-08-29）。ツールを「候補」を出す形に変えたため、そのまま使うと過検出をそのまま申告することになる

### ツールに合わせて本文を書き換えたら、それは欠陥の報告（2026-08-29 Coco決定・恒久ルール）

**検査が書き手の言葉を動かしたら、疑うのは書き手ではなくツール。**

上の「作った側が動かさない」は、ツールを自分で直すことを禁じている。**その代わりに中身を曲げる逃げ道が空いていた。** どちらも同じことが起きる——チェックが意味を失い、しかも誰にも見えない。

- チェックを通すために本文の言い回しを変えたくなったら、**変える前に止まる**
- **回避した箇所と、回避前の本文をWチェックに渡す。** ツールは自分で直さない
- **見分け方は一つ**：書き換える理由が「そう書きたいから」ではなく「**チェックが通らないから**」なら、それ
- **実例（2026-08-29）**：th_15 に「呼吸を**数え**ているあいだ」と書いたところ、`full_check.py` の処方判定が語幹「数え」に当たって、この投稿を佇まい枠から外した。セッションは本文を「ゆっくり息を吐いているあいだ」に書き換えて回避し、**そのことを報告した**。処方ゼロの投稿なので**本来は枠に残るのが正しく、直すべきはツールの側だった**（Wチェックが修正）。報告がなければ、ツールは誤ったまま、言葉だけが静かに痩せていた
- **なぜ報告が要るか**：ツールの誤検出は、回避された瞬間に証拠が消える。**書き換えたあとのJSONを見ても、何が起きたかは分からない。** 回避した本人しか知り得ないので、本人が言うしかない

### 文章のまとめかた：六つの法則

**③比喩一本化プロトコル／目で見る3（比喩の一本化）／目で見る8（抽象語の置き場所）／`rules/posts.md` ルール6 の、共通の土台原則。** 比喩の話だけの原則ではない——**比喩が一つも無い投稿でも、二・三・四は毎回効く**（2026-08-30 明文化。③の下にだけ置いていたため、比喩のない投稿では誰も参照していなかった）。
足して整えない。混ざったら消す。残った一本で刺す。

一．**刃を先に決めて、そこは触らない**
一番強い一行を特定する。直しは全部その周りで起きる。刃を書き換えたら、別の文章になる。

二．**一文章＝一系統**
比喩も語彙も、一本に統一する。同じ行為を二つの言葉で呼ばない。意味は同じでも、読者の中で線が切れる。伝わりにくさの正体は、ほぼこれ。

三．**因果は飛ばさず、動作で繋ぐ**
AだからB、を抽象語で置かない。「攻撃をやめたら」ではなく「その一言をのみ込んだら」。絵を結べる動作にすると、飛びが消える。

四．**頭と尻をブックエンドにする**
一行目に開いたものを、最終行で閉じる。「負けだった」で開けたら「勝ちだった」で閉じる。開きっぱなしの言葉を残さない。

五．**締めの回収先を本文と揃える**
最後の問い、または言い切りが、本文で使った言葉に着地しているか確認する。締めだけ別の語に寄りかかると、そこで線が切れる。

六．**常に引き算**
足して整えない。混ざったら消す。残った一本で刺す。迷ったら、削る方を試す。
※ここでの「引き算」は**編集の姿勢**。読者に渡す処方の引き算（`rules/posts.md`「引き算の処方」）とは別のもので、同じ語だが混ぜない

順序にも意味がある。一で軸を固定 → 二で系統を絞る → 三で因果を詰める → 四・五で回収 → 六が全工程の姿勢。
