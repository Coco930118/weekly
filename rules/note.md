# noteの作り方

`notes/note_*.json` を作る・直すときに読む。原理と持ち場は `CLAUDE.md`。

---

## note作成の土台ルール（毎回必ず適用・最優先）
noteを作成・グローアップする際は、**必ず `main` にある最新週のX（14本）とThreads（21本）＝35投稿を土台にする**。
- 起点は `posts/week_YYYY-MM-DD_YYYY-MM-DD.json`（最新週）の `note_funnel: true` 投稿のみ。診断（X診断・Threads診断）はテーマ判断の材料にするだけで、リンク起点にしない。
- 作業ブランチが古い場合は、まず `main` を基点に作り直してから着手する（バックカタログを壊さない）。
- X由来note＝組織『温度の整え方 —— 組織と仕事』、Threads由来note＝関係『距離の整え方 —— 恋愛と関係』。1本のnoteにX由来とThreads由来を混ぜない。
- 各noteの公開日（publish_date）は、予告した投稿の投稿日と一致させる。
- **新規に作るnoteの「あわせて読む」は、そのnoteの公開日（publish_date）より前に公開された記事のみを使う**。未来・同日公開の記事はリンクしない。同じ週に作る2本は、後発note→先発noteの一方向でリンクを張る（先発noteから後発noteへは張らない）。
- **例外：すでに公開済みの記事に、あとから「おすすめ記事」を足すときは、公開日の前後を問わない**（2026-08-24 Coco決定・恒久ルール）。日付ルールの目的は「公開時点でまだ存在しないURLを載せない」ことなので、**すでに全部公開されている過去記事どうしでは、この前提が成り立たない**。古い記事から新しい記事へ推すのは、note内の回遊を増やす正しい形。同プランであることだけは守る
- **常設案内へのリンクは日付ルールの対象外**（常時公開のため）

### 週の内訳（2026-08-30 明文化）
**funnel note 8本＋無料の案内記事1本＝週9本。** funnelの起点は `note_funnel: true` の投稿（週8本）で、無料1本は別枠（下記）。**用量ルールの「週9本のうち3本まで」はこの内訳を指す。**

## 週1本、無料の案内記事を別枠で足す（2026-08-24 Coco決定・恒久ルール）
**背景（実測）**：2026-08-18週のnote週間ビューは、公開済み114本の合計で**29**（1記事あたり週0.25）。原因は、**114本中108本がメンバー限定で、無料公開が実質ゼロ**だったこと。メンバー以外には本文が見えないため、note内の検索・おすすめ・タグからたどり着いた人が読者になる経路が塞がれていた。一方でスキ率は17%と高く、**流通の問題であって内容の問題ではない**。

- **週8本のfunnel noteは、すべて `members_only` のまま。無料にしない**（週8本の価値を削らない）
- **別枠で、案内型の無料記事を週1本足す**。週の合計は9本になる
  - `visibility: "public"` ／ `price: "0"` ／ `free_ratio: "1.0"` ／ `tier: "free_entry"`
  - `funnel_targets` は空。SNS投稿の予告とは紐づかない独立記事
- **プランを毎週交互にする**。組織 → 恋愛 → 組織…。両プランとも1,000人が目標なので、入口を片側に寄せない
- **その週の記事に紐づけない**。同じ週の記事にリンクすると同日リンクが発生してルール違反になるため、あわせて読むは**前週以前の同プラン記事2本**にする
- **角度は毎週変える**。常設案内2本（`向かない人から先に書く`）と同じ切り口を繰り返さない。例：「答えは配っていない。決め方のほうを置いている」「どんな夜に開く場所か」「一週間の使い方」
- 中身の必須要素：**①何を置いていて何を置いていないか ②向かない場面（先に書く） ③費用と定番プロミス ④在り方署名＋背中押し**
- 完成後チェック：その週に `public` の案内記事が1本あるか／前週と別のプランか／funnel note を無料にしていないか／角度が既存の案内記事と重なっていないか

**常設案内2本（`source_week: standing_guide`）は恒久的に `public`**。メンバーシップを売るための記事が有料だと、読める人が既に会員しかいない。

### 週1本の無料枠は「まとめ記事（型A）」で書く（2026-08-25 Coco決定・恒久ルール／9/1週から適用）
**背景（実測）**：2026-08-18週のnote週間ビューは公開114本で29（1記事あたり週0.25）。スキ率は17%と高く、**流通の問題であって内容の問題ではない**。原因は無料記事が実質ゼロで、note内の検索・タグ・おすすめからたどり着く経路が塞がれていたこと。**足りないのはストックではなく、既存ストックへ人を連れてくる無料記事**（2026-08-25時点で有料110本に対し無料5本）。

- 週1本の無料枠は、**既存の有料記事8〜10本を一つのテーマで並べて紹介する「まとめ記事」**にする。中身は要約まで、処方は各記事へ送る
- **1本で既存記事8〜10本にリンクが張られる**ので、note内の回遊がいちばん立ち上がる。新規に書く量もいちばん少ない（並べ方だけを新しく書く）
- **未来の週のぶんを先に作らない**（2026-08-25 Coco指示）。**その週が来たタイミングで作る**。先に作ると、どれが公開済みでどれが未アップか分からなくなる
- プランは週ごとに交互（組織 → 恋愛 → 組織…）。既存の無料枠ルール（`visibility: public` ／ `price: "0"` ／ `free_ratio: "1.0"` ／ `tier: "free_entry"` ／ `funnel_targets` は空）はそのまま
- **あわせて読むの1本目は、必ず同プランの有料の代表記事に向ける**。無料で刺さった読者が、有料のいちばん良いところに落ちる形にする
- 型B（既存記事から診断・チェックリストだけを抜いて無料1本にする）と型C（一場面の完結記事・1,500〜2,500字）も使ってよいが、**既定は型A**。型を変えるときは作業報告で理由を書く

## noteタイトルの先頭に、プランの記号を置く（2026-08-24 Coco決定・恒久ルール）
一覧でどちらのプランの記事か判別できるようにする。パレットの色分け（`rules/image.md`「プラン別にパレットを固定する」）と併用する（色＝遠目、記号＝確認）。
- **X由来（組織と仕事）＝ `💼`** ／ **Threads由来（恋愛と関係）＝ `💗`**
- **選定基準は3軸：①意味が一発で通じるか ②小サイズ（一覧の16〜20px）で潰れないか ③プランの範囲を全部カバーできるか。**思想より共通認識レベルを優先する（2026-08-24 Coco決定）
- 落とした候補と理由：`🫶`（手が2つで小さいと潰れる）／`💍`（結婚・婚約に限定され、子育て・友人の記事とズレる）／`💕`（2つ重なって小サイズで塊になる）／`🤍`（装飾に見えて信号にならない）／`👔`（男性コード。女性の中間管理職を弾く）／`🤝`『⚖️`（手・細線で潰れる。⚖️は法律に読まれる）／`🏢`（企業に読まれ「働く人の悩み」感がない）／`🏆💰📈`（成果・金で痛みと合わない）
- **記号は単体でなくペアで読まれる。**💼単体なら副業・転職系に見えるが、一覧に💼と💗が並ぶと「仕事と恋愛の両方を同じ人が書いている」が一瞬で伝わる。これは定番プロミスの構造（原理は7つ、場面は無限）そのもので、ペアにすることでコストが差別化に変わる
- **この記号の仕事は「識別」であって「集客」ではない。**記号が出るのはメンバーシップの記事一覧で、見るのはすでに入会した人か販売ページにいる人。記号で新規が流入する経路はほぼないため、惹きつける力ではなく**一瞬で見分けられる力**で選ぶ。その基準で💼が最も速い（学習ゼロで「仕事のほう」と分かる）
- 払っているコスト：💼はnoteで副業・転職・ビジネスハック系が大量に使う記号。ただし**見る人はすでに導線の中にいる**ことと、**💗とペアで並ぶこと**の二点で中和されると判断した（2026-08-24 Coco決定）
- **1プラン1記号に固定する。**複数を使い分けると読者が学習できず、識別子として機能しない
- 旧案の 💎（X）は不採用。投稿のひとことの X＝💎／Threads＝🫶 が2026-08-24に廃止されたため、揃える根拠が消えた。かつ💎は「組織」を意味しない
- 記号はタイトルの1文字目に置く。**本文中の「あわせて読む」のリンク表記には付けない**（散文が濁るため。`internal_links` も記号なしで持つ）
- `reference/note_archive.json` の `title` は、記事の `title` と同じ形（記号あり）で持つ
- **既存記事への遡及はCocoの判断**（note.com側でのタイトル編集が必要）

## note記事の署名ルール：「最後に必ず在り方に戻る」（毎回必ず適用）

**対象**：note記事（`notes/note_*.json`）を新規作成・グローアップするたび、**全記事に一律**で適用する。「Cocoの記事は最後に必ず在り方に戻る」をブランドの signature として固定する。

### ルール（固定されるのは「在り方に戻る」ことだけ・文型は縛らない）
本文の最後（「あわせて読む」の直前）に、その記事で説明した技術・方法を**「技術ではなく、在り方／立ち位置の話」へ着地させる一段**を必ず入れる。
**固定するのは「必ず在り方に戻る」という原則のみ。締めの文型は定型でも溶け込み型でもよい**（記事の声を殺してまで定型に揃えない）。

### 着地の中身（毎回・記事ごとに固有の角度で）
その技術が“効く条件”は、上手さ（技術）ではなく、書き手の在り方（相手をどう見ているか／何を決めているか／誰を信じているか／何を引き受けているか）だと示す。着地する“在り方の一言”は記事ごとに必ず変える。

### 締めの文型は2タイプから記事に合う方を選ぶ
- **① 定型署名タイプ**（主にX・軍師の断言）：
  - 開き「ここまで〜を書いてきたけれど、最後に一つだけ。」→ 締め「〈技術名〉というのは、〈○○の技術／方法〉に見えて、実は「〈在り方の一言〉」という立ち位置の話でしかない。」
- **② 溶け込み／余韻タイプ**（主にThreads・哲学者の余韻、Xでも可）：
  - 定型構文に頼らず、記事本文の語彙のまま在り方へ着地させる（例：「失うことを受け入れた人だけ」「必要とされなくなることを引き受けている」「いい人だと思われることを手放した人だけ」「今日を選ぶこと」）

### 用量：①の定型は週3本まで（2026-08-25 Coco決定・恒久ルール）
**在り方署名の段の中に、語尾「〜でしかない」で締める文を含む記事は、週9本のうち3本まで。**
- **数え方は広い定義**。「〜に見えて、実は…」の有無は問わない。「道具でしかない」「〜ことでしかない」も1本として数える。1記事に何本あっても1本と数える
- 数える範囲は**在り方署名の段全体**（「あわせて読む」の直前のセクション）。本文中の「でしかない」は対象外
- 残り6本は②。記事本文の語彙のまま在り方へ着地させる。**「にすぎない」「だけだ」への言い換えで数を逃げない**——形を変えるのが目的で、語尾を変えるのが目的ではない
- 理由：①は効くが、週の半分を超えると読者側で「またこの形」になる。**在り方そのものが定型として読まれると、売り物（Being）が一番傷む**。原則（在り方に戻る）は全記事、文型は分散させる
- **配信済みには遡及しない**（新ルールは過去記事に遡及しない、の原則どおり）。検出しても `reference/note_fix_queue.json` に入れるだけ。**生成済み・未配信の週は直す**
- 数えるのは `python3 tools/note_check.py --week YYYY-MM-DD_YYYY-MM-DD`（4本以上で要修正に出る）

### 注意
- **原則（在り方に戻る）は固定・文型と“在り方の一言”は毎回変える**。定型に揃えることより、記事の温度に合う着地を優先する
- content_markdown と content_html の**両方**に入れる（挿入位置は「あわせて読む」の直前、独立した `---`／`<hr>` セクションとして）
- X・Threads どちらのプラットフォーム記事にも適用する（Xは①が多め、Threadsは②が自然だが、確定稿の声を優先して選ぶ）
- 既存の「あわせて読む」内部導線・メンバーシップCTA・visibility設定は維持したまま、その手前に差し込む

### 自己チェック（新規作成・グローアップのたびに必ず実行）
- [ ] **全記事**に在り方の一段が入っているか（1本でも欠けていたら未完了）
- [ ] 位置は「あわせて読む」の直前、独立した `---`／`<hr>` セクションになっているか
- [ ] content_markdown と content_html の**両方**に入っているか
- [ ] “在り方の一言”が記事ごとに違う角度になっているか（週内で使い回していないか）
- [ ] **①の定型（「〜でしかない」で締める）が週3本以内か**（広い定義で数える）

## note完成後チェック：ブランド整合性と到達力（毎回必須・全記事）

noteを新規作成・グローアップするたびに、以下の3項目を必ず実行する。**照合先の正典は `reference/brand_profile.json`**（商品名・媒体別ポジショニング・4媒体のプロフィール文面・ターゲット2層・戦略マップ）。毎回読み込んでから判定する。修正が必要な場合は**提案のみ**行い、勝手に確定しない（Cocoの判断を待つ）。

**運用範囲**：本リポジトリの対象は X / Threads / 各診断 / note。**Instagram は正典に記録のみで運用対象外**——投稿生成もチェックもしない。ただし「Instagramの世界観（旅・食・日常）が他媒体に混ざっていないか」だけは③の混線チェックで見る。

### ①ブランド整合性チェック
- 商品名『**関係の温度と距離を整える技術**』の枠内に収まっているか（別商品の話になっていないか）
- **媒体の役割が入れ替わっていないか**——X由来note＝組織・仕事の角度／Threads由来note＝恋愛・関係の角度。プロフィールを見て来た読者の期待とズレていないか
- Xの立ち位置が**翻訳者**（温度調整しながら橋渡しする役割）になっているか。厳しい構造分析コンサル・切って捨てる側に寄っていないか
- ターゲットが正典の2層（板挟みの中間管理職・想いが届かない経営者／恋愛・夫婦・子育て等で距離に悩む読者）に向いているか
- **「やり方（How）」の羅列で終わらず、「在り方（Being）」に着地しているか**（＝在り方署名ルールと連動。Beingがブランドの売り物）
- 数字は `CLAUDE.md`「使える数字は4つだけ」の範囲か（**4つ**・臨機応変枠は店舗/法人向けの回・**週内3本まで**・**1〜2行目に置かない**）。ここには複製を置かない（2026-08-30 訂正——ここだけ「3つだけ」になっていて、正典と本数が違っていた）
- **一人称が「わたし」になっているか**（note本文も含め全媒体で統一。プロトコル等に「私」とある場合も「わたし」を優先する。既存記事タイトルの引用だけは原表記のまま）

### ②到達力チェック（100万インプレ／月収300万を目指す水準か）
`reference/popular_account_patterns.json`（人気アカウントの勝ち型）と照合する。
- タイトルが「短い断定（詩性）× 現場の痛み」の二層になっているか。抽象で終わっていないか
- **その週のnoteに「覗き見型」のタイトルが最低1本あるか**（`reference/sold_article_patterns.json` の operating_rules 参照・実売が確認できている唯一の型のため週次で固定枠）
  - 覗き見型＝読者に寄り添う型ではなく、**評価する側（上司・経営者・選ぶ側・相手）の内側を開示する**型。建前と本音の落差を含める
  - 例：「本当に代わりがいるなら、上司は黙って替えている」
  - **抽象語ではなく、読者が絵を浮かべられる具体語で書く**（「手が尽きている」ではなく「黙って替えている」）。煽り・不安ドリブンにはしない
- タイトル全般で**抽象語を避け、具体的に絵が浮かぶ言葉**を使う（「関係は決まる」より「翌日に、何を送るか」）
- 冒頭2〜3行で**痛みの名指し**があり、読者の「それ、私だ」を最初の一息で取れているか
- **保存・シェアの引き金**が最低1つあるか——後で使える道具（問い・チェックリスト・テンプレ・紙一枚）／感情に名前がついた一文／スクショ一撃のパンチライン（引用ブロックは1セクション1つ）
- 新情報ではなく、**読者が薄々感じていたことの言語化**になっているか（伸びの核はここ）
- 無料部分だけで「これだけでも価値がある」と感じさせ、原理の核心は寸止めできているか
- 型を借りてもブランドの声（大人の女性の話し口調・凛と品・煽らない・スピ排除）を崩していないか

### ③読了と納得のチェック（8割が読み切って「心が整理された」）
- そのnoteのターゲット層の**8割が最後まで読み切れる**構造か（見出し・改行・引用・箇条書きで縦読みできるか／長い説明の塊がないか）
- 読後に「**なんだか心が整理された**」が残るか。情報が増えただけで終わっていないか
- 一件の場面が片づくだけでなく、**同じ形の悩みが来たときに自分で処理できる**手触りが残るか（Coco Methodology「抜け出す」の定義）
- 媒体をまたいだトーンの混線がないか（Instagramの世界観＝旅・食・日常が、X/Threads/noteに混ざっていないか）

### 出力形式
note ID → ①②③の判定（OK／要修正）／要修正の具体箇所と修正案／Cocoの判断に返す箇所の明示。

## note記事の6項目チェック（2026-08-17 Coco承認・恒久ルール）

**対象**：週次深堀りnote（`notes/note_*.json`）の新規作成・グローアップ。**適用開始＝2026-08-11週のnote以降**（それ以前のバックカタログには遡及しない）。常設案内note（`source_week: standing_guide`）は6項目を章立てで持つため対象外。

**6つの見出しをそのまま章立てにはしない。** 章立ては現行の勝ち型（相談引用→実話→原理→道具→CTA→在り方署名→背中押し）のまま、全noteが以下6つの問いに本文のどこかで答えているかをチェックする。

| # | 読者の問い | 満たし方 |
|---|-----------|---------|
| ① | 自分に向いているか | 冒頭の相談引用・痛みの名指し（既存ルールで担保） |
| ② | 何が変わるのか | `outcome_promise` の中身が本文で言語化されているか |
| ③ | 変化までどれくらいか | **固定スロット**：具体策の直後に1〜3行。正直な時間感で、即効を匂わせない（例：「今夜からできる。ただし相手の反応が変わるのは、だいたい三回目から」） |
| ④ | 自分でやることは何か | 道具が1つ・数えられる形（既存ルールで担保） |
| ⑤ | 費用はいくらか | CTAのメンバーシップ部（月額1,500円・定番プロミス） |
| ⑥ | どんな人・場面には合わないか | **固定スロット**：在り方署名の直前に短い一段。「この整え方が向かない場面」を1つ名指しし、その場合の代わり（離れる・専門家・時間を置く等）まで書く。切り捨てルールのnote版＝処方の誤用防止 |

- ③⑥の言い回しは事務語にしない（「向いていない人」ではなく「この整え方が向かない場面」等、その記事の声・語彙で書く）
- ③⑥とも content_markdown と content_html の**両方**に入れる（③は見出しを立てず本文の流れに溶かす。⑥は独立した一段でよい）
- 完成後チェック：6項目のどれかが欠けていたら、該当noteのIDと欠けている番号を名指しして修正案を出す（Cocoの判断を待つ）

## noteの肩の力と輝き（2026-08-23 Coco承認・恒久ルール／35投稿ルール4のnote版）

**対象**：note記事（`notes/note_*.json`）の新規作成・グローアップ。**適用開始＝2026-08-23以降に作るnoteから**（既存バックカタログには遡及しない）。

狙いは35投稿の「ルール4：肩の力と輝き」と同じ。**noteこそ「必死に見えると値段が下がる」場所**——月1,500円を払う理由は「解決してくれるから」ではなく「この人みたいになりたいから」（＝会員の意味＝**「ぐるぐるした時に開く場所を持っておく対価」**／売り物は**在り方＝Being**）。処方だけが詰まったnoteは、正しくても「ずっと働いている人」の顔になる。SNS側で直した顔がnoteで戻るのを防ぐ。

### ① ウィット一滴（週のnoteで1〜2本に一滴）
- 「整った側の軽さ」の一行を本文に一つ置く（例：「拾えたら、あとはビールを開けていい。」「浮いた時間で、アイスを食べてる」）。**笑わせようとしない**
- **数え方は `rules/posts.md` ルール4①が正典**（生活の具体が描かれている一行だけ／処方に溶けている一行は数えない）。**旧例「代わりにお茶を一杯」は2026-08-29に廃止**——「代わりに」は“やめたあとの代わり”＝処方の一部で、「数えない②」と食い違っていた（2026-08-30、note側に残っていた同じ例を差し替え）
- **位置は、道具（具体策）を渡した直後か、6項目チェック③「変化までどれくらいか」のスロットの近く**
- **最終行は背中押しのまま動かさない**（在り方署名 → 背中押しの順は崩さない）。ウィットを最後に置くと、背中押しの静けさが濁る
- 35投稿の週5〜6本と同じ比率では入れない。noteの分量では効かずに散るため、**週のnoteで1〜2本**に絞る

### ② 在り方署名に「整った側の風景」を置ける（佇まい枠のnote版）
- 35投稿の**佇まい枠（処方ゼロ投稿）はnoteには作らない**。処方ゼロのnoteは6項目チェック④「道具が1つ・数えられる形」を満たせず、定番プロミス「毎週深堀りが増えて」の中身が空になる。憧れの風景は**無料側（伴走）の役割**
- 代わりに、**在り方署名の一段に「整った側の風景を一場面」入れてよい**。抽象の一言だけで着地するより絵が残る。条件は既存の署名ルールのまま（記事ごとに固有の角度／content_markdown と content_html の**両方**／「あわせて読む」の直前）

### ③ Xの締めの緩和はnoteに適用しない
- noteの最終行はすでに背中押し＝整った側から手を当てる形になっており、緩和の余地がない。本文中の「わたしはこうしてる」を観察形にする程度で足りる

## note記事の締めルール：「最後に背中を押す」（毎回必ず適用・全記事に一律）

**対象**：note記事（`notes/note_*.json`）の全記事。**在り方署名の最後**（＝「あわせて読む」の直前）に置き、本文の最終行にする。SNS投稿（X・Threads・診断）は従来トーンを維持し、本ルールの対象外。

### 原則
**厳しく見えて、最後は背中に手を当てる。これがCocoの良さ。**
現場の痛みを構造で切ったあと、読者を突き放したまま終わらせない。最後の一押しまで含めて、Cocoの署名とする。

### 形（二段で書く）
1. **テーマに合わせた一言**（その記事の具体策・場面を受けた、記事ごとに固有の一行）
2. **背中押しの言い切り**（「あなたなら、〜」「大丈夫。〜」）

例：
| 記事テーマ | 締め |
|-----------|------|
| 惰性と安定 | 今日、小さな「ありがとう」をひとつ。それで十分。／あなたなら、できる。 |
| 比べてくる人 | あなたの物差しは、あなたが持っていていい。／大丈夫。あなたはもう、自分の道を歩いている。 |
| 本音が言えない | 焦らなくていい。今日は、一文書くところから。／あなたなら、できる。 |
| わかってくれない | 伝え方は、今日から変えられる。／あなたなら、大丈夫。 |
| 怒りの正体 | 怒りに気づけた時点で、もう半分進んでいる。／あなたなら、できる。 |
| 嫉妬 | 羨ましいと感じる心は、動きたがっている心。／大丈夫。あなたなら、進める。 |
| 自分を大切に | 今日のあなたを、まず、あなたが大切に。／大丈夫。ちゃんと、変わっていく。 |

### 条件（これを外すと安っぽくなる）
- **具体策を渡した後にのみ置く**。「今日できること一つ」「問い」「チェックリスト」のいずれかを出したうえで押す。中身のない励ましにしない
- **文言は毎回変える**。テーマに合わせて言い換える（「作れる」「渡せる」「決められる」「戻ってこられる」「頼れる」等）。同じ週に同じ言い切りを2本以上使わない
- **押し付けず、静かに言い切る**。凛とした品を保つ。感嘆符・煽り・テンションの高さは入れない
- **不安煽り・スピリチュアル・過剰な自己啓発調はNG**（従来通り）
- content_markdown と content_html の**両方**に入れる。JSONの `closing_push` に締め全文を控える

### 自己チェック
- [ ] 全noteの最終行が、テーマ固有の一言＋背中押しの二段になっているか
- [ ] その押しの直前に、具体策（一つの行動・問い・チェックリスト）が渡されているか
- [ ] 週内で同じ言い切りが重複していないか
- [ ] 在り方署名の後・「あわせて読む」の前、という位置になっているか
